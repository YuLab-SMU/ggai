# Literature and ecosystem survey: semantic / interactive representations of exported charts

Prepared 2026-11-07 for the ggai idea `idea/2026-11-07-agentic-semantic-svg.md`.
Scope: academic and engineering prior work on turning static or exported charts into semantic and/or interactive representations, positioned against the ggai proposal (deterministic skeleton, then agent-authored semantics, then deterministic compile, then verification against data and pixels; "the agent annotates, never redraws").
ggiraph, gridSVG, Shiny nearPoints, InteractiveComplexHeatmap, canvasXpress and plotly ggplotly are covered by other threads and appear here only for positioning.

Verification legend: **[V]** title, authors, venue, year and URL checked against a primary page (publisher, arXiv, ACM/IEEE/Wiley, ACL Anthology, project page or repo) during this session. **[V-arXiv]** checked on arXiv only; no peer-reviewed venue confirmed. **[U]** not verified; treat as a pointer.

---

## 0. Headline findings

1. **Nobody found does the exact ggai pipeline.** No system combines (a) export-time deterministic binding of SVG elements to the real plotting code, graphics state and built data, (b) an LLM that adds open-world semantics such as domain meaning, relations and a per-figure interaction design, and (c) verification of the LLM's claims against the data plus a pixel diff. Each piece exists separately.
2. **The closest engineering prior art is in R and is very recent: `maidr` (xability/r-maidr, on CRAN).** It already does the ggai Stage 1 (L1–L2 skeleton) for ggplot2, Base R, lattice, patchwork, pheatmap and, since **October 2026, ComplexHeatmap** (heat cells, simple annotation tracks, dendrograms; marked experimental). It forces and grabs the grid scene, redraws each grob onto svglite with **invisible text markers between batches**, and rewrites the output with gridSVG-style ids. It extracts data from `ggplot_build()`, writes CSS selectors per element, and ships a fixed accessibility runtime (keyboard, screen reader, sonification, braille, AI chat). It is closed world: about 40 hand-written per-geom processors, and an unknown layer yields empty data. It has no agent-authored semantics, no relation model beyond colour groups, no per-figure interaction design and no verification gate. **This changes two claims in the idea doc.** ComplexHeatmap is no longer a construct "programmatic converters cannot handle", and order alignment already has a working, production-tested solution.
3. **The closest academic work is post-hoc LLM semantics over deployed SVG without code or data**: Cohort-based Semantic Labeling (CSL, arXiv 2026), which produces what it calls **"Semantic SVG (SSVG)"**; Athanor (arXiv 2026, MLLM → interactive static charts); DIVI (VIS 2023, heuristic, handles ggplot2/matplotlib SVG); DataWink (VIS 2025); Chart2SVG (arXiv 2026). They reach L1 at F1 or accuracy of about 0.82–0.86, infer L2 from geometry, and can never check it against the true data. That gap is ggai's opening.
4. **Two naming collisions**: "Semantic SVG/SSVG" (CSL 2026) and the L1–L4 levels, which Lundgard & Satyanarayan (VIS 2021) already use for the semantic content of chart descriptions. Rename or map explicitly.

## 2. LLM / VLM approaches (2023–2026)

### 2a. Making static charts interactive or editable with LLMs (closest to ggai's goal)

- **Athanor**: Liu, Lee, Chen, Jiang, Wen, Wang, arXiv 2601.17736 (Jan 2026; v2 retitled "From Static to Interactive: Authoring Interactive Visualizations via Natural Language") [V-arXiv]. The input is an existing SVG chart. A headless browser flattens it into "SimVec" (up to 90% fewer tokens). An MLLM classifies element roles from SimVec plus the bitmap, scales and data are recovered from axes and legends, and the result is a **constraint model** (Liu et al., "A Spatial Constraint Model for Manipulating Static Visualizations", ACM TiiS 14(2) 2024, https://doi.org/10.1145/3657642 [V]). A multi-agent analyser turns natural-language instructions into an *action → modification* interaction space (tooltips, reference lines, filter, re-encode). It preserves appearance but **replaces marks with control points**, and has no ground-truth data. Evaluation: 2 case studies + 11 interviews; no accuracy numbers. Precursor: Liu, Yu, Guo, Zhuang, Luo, Yuan, "Breathing New Life into Existing Visualizations", arXiv 2404.06039 [V-arXiv].
- **FigAct**: Xiao, Wang, Siu, Laidlaw, Healey, arXiv 2609.36190 (Sep 2026) [V-arXiv]. Acts on a scientific figure's **existing graphical elements** to answer a question: narration beats grounded in elements, plus attention actions. Uses hierarchical element search (about 40× fewer tokens) and an RL-trained 8B model; ships a human-verified benchmark.
- **LLM-native figures / Nexus**: Wang, Sheng, Shao, Qian, Li, Cao, Wang, "Figures as Interfaces: Toward LLM-Native Artifacts for Scientific Discovery", arXiv 2604.08491 (2026) [V-arXiv]. Each figure embeds data subset, code and spec, with an explicit **bidirectional mark ↔ data-row mapping**. Same thesis as ggai ("once exported it's just pixels"), but figures are generated inside their own system rather than annotating arbitrary R output.
- **IVG / iPlotBench**: "Beyond Pixels: Introspective and Interactive Grounding for Visualization Agents", arXiv 2604.21134 (2026) [V-arXiv; author list not checked]. Agents query the Plotly JSON spec rather than pixels to verify values, and add deterministic symbolic metrics in place of VLM judges.

### 2b. Chart-to-code and SVG-understanding benchmarks (the "redraw" family)

- **ChartMimic**: Yang, Shi, Liu, Shui, Wang, et al., ICLR 2025, https://arxiv.org/abs/2406.09961 [V]. 4,800 (figure, instruction, code) triplets, 18+4 types; GPT-4o scores 81.2 (Direct) / 83.2 (Customized).
- **Plot2Code**: Wu, Liang, Ge, Guo, Lu, et al., Findings of NAACL 2025, https://aclanthology.org/2025.findings-naacl.164/ [V]. 368 plots, including R plotly.
- **ChartCoder**: Zhao, Luo, Shi, Chen, Wang, Che, Liu, Sun, ACL 2025, https://aclanthology.org/2025.acl-long.363/ [V]. Chart2Code-160k.
- **ChartEdit**: Zhao et al., Findings of ACL 2025, https://aclanthology.org/2025.findings-acl.185/ [V]. Code-level score 59.96 without source code vs 89.96 with it for GPT-4o. **Having the original code is the single biggest lever**, which supports ggai's code-canonical design.
- SVG benchmarks: **VGBench** (arXiv 2407.10972 [V-arXiv]; LLMs are notably weaker on raw SVG than on TikZ or Graphviz, which carry higher-level semantics), **SVGenius** (ACM MM 2025, https://doi.org/10.1145/3746027.3758287 [V]), **InternSVG/SArena** (arXiv 2510.11341 [V-arXiv]), SVGEditBench [U]. None of these targets chart *role* labelling. VisAnatomy and CSL are the relevant chart-specific evaluations.

### 2c. Verifying LLM claims against data

- Blanco, Zong, Satyanarayan, "Chart-Supported or Model-Supplied? Examining MLLM-Generated Claims for Accessible Visualization", arXiv 2607.25021 (2026) [V-arXiv]. Claims are labelled **Direct / Derived / Speculative**. Supplying structured context (data tables, screen-reader trees) shifts claims toward Direct, and 73.9% of "real-world significance" claims are Speculative. Their worked example (342 rendered penguins vs 344 source rows) shows that **verification must check against the built, filtered data, not the raw table**, which is exactly ggai's built-row vs raw-row binding issue.
- VisText: Tang, Boggust, Satyanarayan, ACL 2023, https://aclanthology.org/2023.acl-long.401/ [V]. Charts as image + data table + **scene graph**; L1 and L2/L3 captions.
- Engineering examples of deterministic numeric verifiers: CivicInsight (github.com/shahfazal/civicinsight) [V-repo only]; `ggaltdata` (CRAN 2026, "every number in the text is a number that is drawn", no LLM, https://doi.org/10.32614/cran.package.ggaltdata) [V].

**Is anyone doing the exact idea?** No. The axis the field lacks is *ground truth at export time*. Post-hoc systems (CSL, Athanor, DIVI, Chart2SVG, DataWink, FigAct) infer L1/L2 from the SVG and cannot verify them. Systems with ground truth (maidr, Vega, Nexus) either have no open-world LLM semantics layer (maidr, Vega) or own the renderer (Nexus). ggai's distinctive combination is **real R code + `ggplot_build()` + grob tree + agent + verification gate + no redraw**, applied to arbitrary R figures including extensions.

## 3. Accessibility standards and systems

- **WAI-ARIA Graphics Module 1.0**, W3C Recommendation 2 Oct 2018, https://www.w3.org/TR/graphics-aria-1.0/ [V]. Three roles:
  - `graphics-document`: the root of a structured graphic. It may be nested, and the spec says a matrix of chart panels should give **each panel** `graphics-document`. Fallback: `role="graphics-document document"`.
  - `graphics-object`: a semantic sub-component that may itself be nested. Collections of disconnected objects should use `group` or `list`, and layout-only `<g>` should get no role or `none`. Fallback: `graphics-object group`.
  - `graphics-symbol`: an atomic symbol whose meaning matters more than its look, with presentational children. Use `aria-roledescription` to name the symbol type. Fallback: `graphics-symbol img`.
  - Companion **Graphics-AAM 1.0** is also a Recommendation. **SVG-AAM** is still a Working Draft (21 Oct 2026, https://www.w3.org/TR/svg-aam-1.0/) whose status note says "early draft … do not implement" [V]. It maps `<title>` and `<desc>` to accessible name and description.
- **Vega ≥ 5.11 / Vega-Lite ≥ 4.14** [V: vega v5.11.0 release notes; vega-lite PR #6391]. These add automatic `role` and `aria-roledescription` on mark-group `<g>`, `aria-label` captions on axes and legends, `aria`/`description` properties, and per-item description channels. **Individual items carry no ARIA by default, to avoid bloat.** This is the right default for dense layers.
- **Observable Plot** (https://observablehq.github.io/plot/features/accessibility) [V]: root `ariaLabel`/`ariaDescription`; marks get automatic `aria-label` ("dot", "y-axis tick"); per-datum `ariaLabel` channel; `ariaHidden` for decorative marks.
- **Olli**: Blanco, Zong, Satyanarayan, IEEE VIS Posters 2022, https://vis.csail.mit.edu/pubs/olli/ [V]; code at github.com/umwelt-data/olli. Adapters (Vega, Vega-Lite, Plot, Bluefish) → `OlliVisSpec` → a **hypergraph** (current architecture) → ARIA tree view with a table dialog, filtering and x/y/l jumps. A diagram domain allows hand-authored hyperedges.
- **Data Navigator**: Elavsky, Nadolskis, Moritz, IEEE TVCG 2024 (VIS 2023), https://doi.org/10.1109/TVCG.2023.3327393 [V]. Structure (nodes plus edges with named navigation rules) + input + rendering of a semantic HTML overlay on **any** graphic: SVG, canvas or raster. Edges express non-tree relations.
- **Chartability**: Elavsky, Bennett, Moritz, CGF 41(3) (EuroVis 2022), https://doi.org/10.1111/cgf.14522 [V]. POUR + CAF audit heuristics; usable as a checklist for the compiled output.
- **Four-level model of semantic content**: Lundgard & Satyanarayan, IEEE TVCG 2022 (VIS 2021), https://doi.org/10.1109/tvcg.2021.3114770 [V]. L1 elemental/encoded, L2 statistical/relational, L3 perceptual/cognitive, L4 contextual/domain. **Name clash with ggai's L0–L4.**
- **AChart**: Andrews & Kopel, AccessViz @ IEEE VIS 2024, https://doi.org/10.1109/accessviz64636.2024.00006 [V]. Extends Describler with *non-standard* roles (`chart`, `xaxis`, `datapoint`, `datavalue`, …) and properties (`aria-charttype`, `aria-axistype`). A useful vocabulary, but those roles are not valid ARIA; carry them in `data-*`.
- **AutoVizuA11y**: Duarte, Costa, Bizarro, Duarte, CGF 2024 (EuroVis), https://doi.org/10.1111/cgf.15099 [V]. React wrapper; data passed in; LLM descriptions; keyboard navigation.
- **MAIDR**: Seo, Xia, Lee, McCurry, Yam, CHI 2024, https://doi.org/10.1145/3613904.3642730 [V]; maidrAI: Seo, Kamath, Zeidieh, Venkatesh, McCurry, ASSETS 2024, https://doi.org/10.1145/3663548.3675660 [V]; Py maidr: Seo et al., arXiv 2509.13532 [V-arXiv]. Engineering details in §4.

**Mapping ggai `semantics.json` onto these.** Root `<svg role="graphics-document document">` with `<title>`/`<desc>`. Each facet or patchwork panel is a nested `graphics-document`. Layers, series, axes and legends are `graphics-object group` (or `list` for legend entries). Data marks and legend keys are `graphics-symbol img`, with `aria-roledescription` from the agent ("significance bracket", "dendrogram branch"). Layout `<g>` gets `role="none"`, and gridlines and other decorative elements get `aria-hidden`. Per-mark `aria-label` goes only on sparse layers; dense layers get a table plus a navigation graph. Relations (legend key ↔ series, label ↔ point, bracket ↔ pair) cannot be expressed in the ARIA tree beyond `aria-labelledby`/`aria-describedby`/`aria-owns`, so compile them to **Data Navigator edges or an Olli hypergraph**. Embed `semantics.json` in `<metadata>` or a `<script type="application/json">`. Screen-reader support for graphics roles is uneven (secondary source: accessible-data-interfaces.com [U]), so test with NVDA and VoiceOver.

## 4. Engineering ecosystems

**Python**
- **mpld3** (https://mpld3.github.io) [V]: `mplexporter.Exporter` re-runs `savefig` to lay out the figure, then crawls Figure → Axes → lines/texts/patches/collections/images/legend and calls `Renderer` hooks (`open_figure`, `draw_line`, …). `MPLD3Renderer` emits JSON that mpld3.js redraws in D3. That is a re-render, not an annotation of the exported SVG. Same design ancestry as plotly's matplotlylib.
- **matplotlib SVG backend**: `Artist.set_gid` and `Artist.set_url` [V, docs 3.11]. The official gallery examples "SVG Tooltip" and "SVG Histogram" [V] set gids, `savefig(format="svg")`, re-parse with ElementTree, and inject `onmouseover`/`onclick` + `<script>`. This is the canonical "bind after export via ids" pattern, but done manually per figure.
- **plotly `mpl_to_plotly`** [V: plotly.py issues #1568/#1606, community thread]. In 2018 a plotly developer said "we wrote it as a proof-of-concept and determined that it was too difficult to achieve perfect conversions". In 2020 a maintainer said it "should be considered deprecated … isn't being actively maintained to track deprecations and changes in matplotlib", after it broke on matplotlib 3.3 (`is_frame_like`). Note: the plotly.py CHANGELOG shows a **community revival in 2025–2026** (6.3.1, 7.0.0: native legends, contours, step plots, violins). The lesson still holds: re-implementing a plotting library's semantics drifts with upstream.
- **py-maidr** [V-arXiv 2509.13532; docs py.maidr.ai]. Patches matplotlib drawing methods (Patch, QuadMesh, Line2D, PathCollection) to assign a unique `gid` per primitive at draw time, injects a `maidr` attribute during SVG serialisation, and embeds the plot schema as `maidr-data` on the root. **This is "bind data to the exported SVG at export time" for matplotlib/seaborn.**
- **Bokeh**: data lives in `ColumnDataSource` and HoverTool reads columns, so it is semantic by construction [V docs]. Canvas by default, SVG/WebGL backends optional [U, not re-fetched].

**Web grammars (semantic by construction)**: Vega-Lite and Observable Plot (see §3). They bind data to marks and emit ARIA, but **require authoring in their grammar**.

**R**
- **ggvis**: "currently dormant" (README) and the GitHub repo was **archived on 10 Feb 2026** [V]. Still on CRAN as 0.4.10.
- **vegawidget**: htmlwidget for Vega/Vega-Lite (VL 4 and 5) with a low-level API and `vw_to_svg()` [V]. **r2d3**: binds R data into hand-written D3 scripts [V]. Both are semantic by construction and need a rewrite.
- **svglite** [V, NEWS]: top-level `id` on `<svg>` since 2.0.0; groups / affine transforms / blending since 2.2.0. These are R graphics-engine compositing groups, **not semantic grob ids**. No per-element ids or data attributes, which confirms the idea doc's spike.
- **rvg** [V]: DrawingML devices (`dml_pptx`, `dml_xlsx`) for editable Office vector graphics. Not SVG, and no data binding.
- **maidr (R)** [V: CRAN README, repo xability/r-maidr, file `R/svg_export.R`, commits 2026-09-26 "export charts with svglite instead of gridSVG (#334)", 2026-10-16/17 ComplexHeatmap support (#386, #394, #395)]:
  - **Export**: `grid.force()` + `grid.grab()` the scene. Walk it the way gridSVG did, redrawing each grob onto a fresh svglite page with an **invisible text marker before each drawing batch**. Read the markers back and strip them, then rewrite into gridSVG-compatible ids (`<name>.<k>.<i>`, viewport-path `<g>`s, `<use>` per point). If a rect or circle grob emits an unexpected number of shapes, redo it **one element at a time**. Hot paths are in C++ (Rcpp).
  - **Semantics**: about 40 R6 per-geom "layer processors" (ggplot2, Base R through function patching, lattice, patchwork, pheatmap, ComplexHeatmap). Each reads `ggplot_build()` or the object, produces data plus CSS selectors, and splits colour-grouped points into legend-named layers. Unknown layers produce empty data and no selectors (closed world).
  - **Runtime**: maidr.js, with keyboard navigation, screen reader, sonification, braille/DotPad and an LLM chat. Interaction is fixed (accessibility-first), not per figure.
- **Data-after-the-fact tools**: in R, maidr is the only one found that binds data to an already-rendered, device-faithful SVG without asking the user to rewrite the plot (ggiraph needs `*_interactive` geoms; gridSVG needs garnishing). In Python: py-maidr and the manual matplotlib gid recipe. In JS, post hoc: DIVI, CSL, Athanor, ChartDetective. Small R a11y helpers that read the ggplot object (not SVG): `ggalttext`, `ggaltdata`, `a11yviz` (r-universe), `autoAlt` (BrailleR + ellmer) [V repos/CRAN pages].

## 5. Positioning

Levels follow the idea doc: L0 geometry, L1 structure, L2 data binding, L3 domain meaning, L4 interaction intent. "Exact" means read from the real binding; "inferred" means estimated from geometry or text.

| Approach family (examples) | L1 | L2 | L3 | L4 | Open vs closed world | Geometry fidelity | Engines covered | Needs code rewrite? |
|---|---|---|---|---|---|---|---|---|
| Raster reverse engineering (ReVision, Poco & Heer, DePlot-style) | inferred | inferred (approx. values) | — | — | Open input, closed chart-type vocab | Lost (output is a spec/table or redesign) | Any image | No |
| DOM-binding deconstruction (D3 Deconstructor, Harper 2018, Hoque 2020) | exact-ish | **exact** (bound `__data__`) | — | restyle only | Closed (linear/categorical mappings) | Preserved | D3 only | No |
| Heuristic SVG deconstruction (Mystique, DIVI, ChartDetective) | inferred | inferred; DIVI links to supplied source data | — | DIVI: fixed taxonomy (select/filter/brush/zoom/sort) | Closed vocab, basic chart types | Preserved | Any SVG tool incl. ggplot2/matplotlib (basic charts) | No |

**Where ggai is novel.** (1) An open-world agent layer that is *grounded in the real code and built data*, not in SVG geometry. (2) Relations as first-class output: legend ↔ series, label ↔ point including ggrepel, bracket ↔ group pair, annotation track ↔ cluster, tree tip ↔ label. (3) A per-figure interaction design compiled into a fixed runtime. (4) A verification gate that checks agent claims against `ggplot_build()` rows, plus a pixel diff. (5) Coverage of extension geoms and custom grobs that per-geom converters skip.

**Where it is not novel.** Element ↔ grob ↔ data binding for ggplot2/base/patchwork/ComplexHeatmap (maidr already does it, along with gridSVG, ggiraph and ggplotly). LLM role labelling of SVG elements (VisAnatomy, CSL, Athanor). The term "Semantic SVG" (CSL). ARIA output (Vega, Plot). The "figure embeds provenance" thesis (Nexus). The "annotate, don't redraw" stance (DIVI, CSL, DataWink, FigAct also keep the original marks).

## 6. What ggai should borrow

1. **Reuse or interoperate with r-maidr's exporter for Stage 1.** The marker-batch walk with a one-at-a-time fallback addresses the idea doc's main risk, order alignment, better than the pick-render hedge. Also emit the **MAIDR JSON schema** (`subplots[][].layers[]` with `type`, `selectors`, `data`, `axes`; https://maidr.ai/docs/SCHEMA.html) as one compile target, which gives keyboard navigation, sonification and braille for free. Then position ggai's agent as the layer that fills maidr's unknown-layer gap (open world) and adds relations, L3 and L4.
2. **Adopt VisAnatomy's label schema and use the corpus for evaluation.** Per-element `type`/`role` (Main Chart Mark, X/Y Axis Tick/Line/Label/Title, Legend Title/Label/Mark, gridlines), `grouping` with `layout`, per-element `encodingInfo`. Use its R-produced subset and LLM4Semantics as the baseline (mean F1 ≈ 0.84; GPT-4o 0.69 on R charts) for an "agent without skeleton" ablation. Use CSL's 6-role taxonomy and its cohort finding (group primitives before prompting) to shape the compressed skeleton.
3. **ARIA mapping as in §3**, with Vega's default of no per-item ARIA unless described and Plot's `ariaHidden` for decorative marks. Relations compile to **Data Navigator node/edge graphs** (or an Olli hypergraph), not to the ARIA tree. Put AChart-style chart roles in `data-*`, not `role`.
4. **Verification vocabulary**: tag every agent claim **Direct / Derived / Speculative** (Blanco, Zong, Satyanarayan 2026) and verify Direct claims against *built* (post-stat, post-filter) rows. Use Lundgard & Satyanarayan's four levels for the a11y text, and rename ggai's L-levels (for example S0–S4) to avoid the clash.
5. **Closed vocabulary for L4**: DIVI's target × interaction-type × input → required-metadata taxonomy (or Athanor's action → modification space) as the JSON enum the agent must choose from. As in Chart2SVG, forbid the agent from inventing role types outside the schema.
