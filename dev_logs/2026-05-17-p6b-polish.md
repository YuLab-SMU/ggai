### Finding (1): the "S7 quirk" wasn't

P6's dev log filed a TODO claiming patchwork's S7-prototyped ggplot stored `$layers` unreliably on patches. Re-investigation in P6.b showed:

- `pw <- p1 + p2 + p3` where p1=1 layer, p2=2 layers, p3=3 layers.
- `length(pw$layers)` returned 3 (matches p3).
- `length(pw$patches$plots[[1]]$layers)` returned 1 (matches p1).
- `length(pw$patches$plots[[2]]$layers)` returned 2 (matches p2).

So direct `$layers` access works perfectly. The earlier confusion was about **storage order**: I had assumed `self = first plot, patches = rest`, but patchwork's `+` operator does the opposite — **self = last-added, patches = earlier plots in original order**. So `patches[1] = p1, patches[2] = p2, self = p3` in the example.

My P6 inspector had put `self` at panel index 1 and patches at indices 2..N. The render order is `patches[1], patches[2], ..., self`, so visually self is the LAST panel, not the first. Fixed.

### Finding (2): operator semantics

- `p1 + p2` between two ggplots: `$layers = p2$layers`, `patches = [p1]`. The result is a "+-built" patchwork with a visible self panel.
- `p1 / p2` between two ggplots: same shape as `+`. Self = last-added.
- `p1 | p2` between two ggplots: same shape as `+`. Self = last-added.
- `p1 | (p2 / p3)` where the right operand is already a patchwork: produces a **container** patchwork. `$layers` is empty; `patches = [p1, (p2/p3)]`. No self panel.
- `wrap_plots(list(...))`: same as `+` — produces a +-built patchwork with self = last in list. Not a container despite the function name.

So the "container" pattern is specifically: **one operand is itself a patchwork**. The inspector now detects this via `length(pw$layers) == 0`.

### Finding (3): nested recursion was small

Once container detection is in place, recursion drops out cleanly. When a `patches[[i]]` is itself a patchwork, the inspector calls itself on the nested object and embeds the returned `panels` sublist under `kind = "nested_patchwork"`. Total leaf-layer count walks the tree to sum all ggplot/patchwork_self entries.

### Finding (4): webshot2 just works

After `install.packages("webshot2")` (which pulls `chromote`), the existing `render_htmlwidget()` PNG path activated transparently:
- L2 smoke: `ggai_execute_and_capture(plotly_code, format = "png")` produced a 50KB+ PNG with cylinder color coding.
- Agent end-to-end: `ggai("@mtcars interactive plotly scatter ... Save as PNG")` self-routed to `ggai-htmlwidget`, the renderer wrote the PNG without any code change. **39.7 s wall time.**

The htmlwidget PNG path is now a real, exercised flow on this machine.

### Cosmetic gap

The agent's plotly PNG retained plotly's interactive toolbar (camera, zoom, lasso icons) in the top-right corner. The `ggai-htmlwidget` skill mentions `config(displayModeBar = FALSE)` for "embedded use" but doesn't make it the default for PNG export. The agent followed the more permissive option. Worth tightening next iteration of the skill, but not blocking. Filed as a small follow-up.

## Notes for the future

- **Patchwork operator semantics matter for inspect.** If patchwork ever changes its container vs +-built convention, my detector should be revisited. For now `length(pw$layers) == 0` is the clean signal.
- **`ggplot_build()` is overkill for layer counting.** It builds the full plot (including running `geom_smooth` etc.) just to count rendered layers. Direct `$layers` access is faster and equally reliable in current patchwork. `count_layers_safe()` retains `ggplot_build` as a fallback only.
- **The webshot2 path is now hard-coded into the workflow.** No user-visible behavior change, but the htmlwidget smoke evidence is now complete.
